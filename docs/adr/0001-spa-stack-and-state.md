# 0001 — SPA stack, data and state

Status: accepted (2026-10-30)

`asp-fe` is a client-only single-page app: React 19, Vite 8, TypeScript, Tailwind CSS v4 and shadcn/ui
on Radix (ADR-0003). There is no server rendering; the API is `asp-api`, a separate repository.

## Decisions

- **Routing: TanStack Router, file-based** (`src/routes/`, `src/routeTree.gen.ts` generated by the
  Vite plugin, never edited). Chosen over React Router for typed params and search params without a
  framework build layer. Search params are validated with Zod in the route (`validateSearch`), so a
  filter, tab or page number lives in the URL, typed. The router context carries the `QueryClient`.
- **Auth guard** (when the login screen lands): protected routes sit under a pathless `_authenticated`
  layout whose `beforeLoad` reads the Better Auth session and throws `redirect({ to: '/login' })`; the
  tenant panel gets a second layout checking the member role. A guard is navigation, not security: the
  API authorizes every request (asp-api ADR-0004).
- **Server state: TanStack Query v5 with the client generated by `orval`** from the API's committed
  `openapi.json` (asp-api ADR-0009): typed hooks, Zod schemas and MSW mocks. Generation is wired up
  when the API publishes the file. One `customFetch` mutator sends cookies (`credentials: 'include'`),
  parses `application/problem+json` into a typed `ApiError` and is the only place that calls `fetch`
  (lint: `no-restricted-globals`). 401 is handled once, in the `QueryCache`/`MutationCache` `onError`.
  Query keys come from the generated `get…QueryKey()` helpers, never written by hand. A generated hook
  is wrapped in a feature hook only to add behavior (invalidation, toast, mapping), never as a
  pass-through. Route loaders prefetch with `queryClient.ensureQueryData` for what the first paint needs;
  `defaultPreloadStaleTime: 0` leaves caching to Query.
- **Forms: react-hook-form with the Zod resolver**, using the orval-generated schema of the request body,
  and shadcn's `Field` components for labels and errors. Installed with the first form.
- **Client state, in this order**: server data in Query; anything shareable or reload-safe (filters,
  tabs, pagination, selected record) in search params; local UI state in `useState`. A global store
  (Zustand) needs an ADR first. Query data is never copied into state.
- **React Compiler** (`babel-plugin-react-compiler` 1.0 through `@rolldown/plugin-babel`) memoizes every
  component. `useMemo`, `useCallback` and `memo` are banned by lint; the compiler's own rules
  (`react/purity`, `react/immutability`, `react/set-state-in-effect`…) are errors, because a component
  that breaks them is silently left uncompiled. The Rust compiler in `@vitejs/plugin-react` was skipped:
  it is marked experimental.
- **Effects only synchronize with something outside React** (a browser API, a subscription). Derived
  values are computed during render, event logic lives in handlers, state is reset with `key`, and data
  is never fetched in an effect ("You Might Not Need an Effect", react.dev).
- **No i18n library**: the app is pt-BR only; copy is written in the JSX. Dates and numbers go through
  `Intl` with `pt-BR`, wrapped in `src/lib/format.ts` when first needed. Which time zone defines "today"
  for checklists is decided with the first feature that needs it.

## Considered options

- **React Router 8**: typed only in framework mode, which adds a build layer an SPA does not need.
- **TanStack Form**: better inference, smaller ecosystem and fewer examples for agents to follow.
